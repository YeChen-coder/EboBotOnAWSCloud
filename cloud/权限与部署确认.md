## 两个项目角色

| 模板角色 | 谁使用 | 权限与受益资源 |
|---|---|---|
| `ExecutionRole` | AWS ECS/Fargate 执行平台 | 从本栈的 `ebo-cloud/engine`、`ebo-cloud/assistant` ECR 仓库拉镜像；读取本栈的两个 Secrets Manager 配置；向本栈 `/ebo-cloud/engine`、`/ebo-cloud/assistant` 日志组创建日志流并写日志 |
| `TaskRole` | 本任务中的两个容器 | 只允许通过本栈两个 EFS Access Point 挂载、读写本栈的 EFS 文件系统；没有读取 Secrets Manager、操作 ECS、IAM 管理权限 |

执行角色具体 Action：`ecr:GetAuthorizationToken`、`ecr:BatchCheckLayerAvailability`、`ecr:GetDownloadUrlForLayer`、`ecr:BatchGetImage`、`logs:CreateLogStream`、`logs:PutLogEvents`、`secretsmanager:GetSecretValue`。

其中 `ecr:GetAuthorizationToken` 使用 `Resource: *`（该 API 不支持按仓库限定）；实际镜像下载权限仍限定到两个仓库。任务角色具体 Action：`elasticfilesystem:ClientMount`、`elasticfilesystem:ClientWrite`，同时限定文件系统和 Access Point ARN。

两个角色均仅信任 `ecs-tasks.amazonaws.com`，并限制来源账户和区域。角色名称由 CloudFormation 生成。两个同 Task 容器共享 TaskRole，因此这里的权限边界是整个 Task，不能视为容器间隔离。

## AWS 服务关联角色

账户目前没有 ECS/EFS/Backup 服务关联角色。首次使用可能需要 AWS 自动创建：

- `AWSServiceRoleForECS`：ECS 管理任务网络接口和服务相关资源。
- `AWSServiceRoleForAmazonElasticFileSystem`：EFS 管理挂载目标网络等服务资源。
- `AWSServiceRoleForBackup`：本模板开启 EFS 自动备份，AWS Backup 管理备份生命周期。

这些是 AWS 定义的服务关联角色，由对应 AWS 服务使用；其权限范围由 AWS 的服务关联策略定义，通常比两个自定义项目角色更广。确认范围包含 AWS 为上述功能必需创建这些角色，但不包含给任何个人或第三方新增管理员权限。参见 [EFS 服务关联角色](https://docs.aws.amazon.com/efs/latest/ug/using-service-linked-roles.html)、[Backup 服务关联角色](https://docs.aws.amazon.com/aws-backup/latest/devguide/using-service-linked-roles-AWSServiceRoleForBackup.html)。

## 实际影响

创建新 VPC、两子网、出口路由、安全组、加密 EFS 和备份策略、两个镜像仓库、两个配置 Secret、日志组、ECS Cluster、TaskDefinition、Service。初始 DesiredCount 为 0；镜像上传及配置校验完成后再启动一个 2 vCPU / 4 GiB Fargate Task。

ECS Exec 关闭，无远程 Shell 权限，无应用公网入站端口。Task 使用公网 IP 出站访问 AWS、Enabot/Agora 和 OpenAI；没有 NAT Gateway 或负载均衡器。会产生已创建服务的存储、日志、备份等费用，以及运行后的 Fargate、公网 IPv4、网络流量和 API 费用。

EFS、Secret、ECR 仓库保留策略会在删除栈后留下数据；保留部分可能继续收费，清理需要另行明确操作。

确认后可以继续创建上述角色和资源、上传已准备配置与镜像、验证服务，并进行单实例切换。原本地 Home Assistant 保留；切换时先停本地两个业务容器，再启动云端，避免两个 Engine 同时连接机器人。
